FIX
---
R25 correctly persisted Basket drops but then called the normal week-loading path
to verify authoritative state. That path blanked the calendar and displayed the
loading state, which caused the visible white-screen/reload effect.

R26 keeps the authoritative verification but changes automatic post-save refreshes
to a silent background sync:
- optimistic card placement remains visible immediately;
- database save completes;
- fresh authoritative week data is loaded without clearing the calendar;
- the fresh state is rendered in place;
- no white loading screen is shown.

This applies to automatic post-mutation Schedule re-syncs, including Basket group
placement and drag/rearrange operations that require an authoritative reread.

The explicit Refresh button and actual week navigation still use the normal loading
state because those are user-requested loads.
